# Pedal Loop PL5: the contextual UI

**Where it lives.**
- OSP has no playback-settings page.
- The playback-mode key (the One Shot / Granular symbol key in each card's header) already opens a menu of the two modes, each with its symbol, a line on what it does, and a check.
- PEDAL LOOP is a **section of that menu**: a separator, the existing section-header style, then three choices drawn exactly like the mode items (name, a muted line, the fine check). In order:
  - **Normal:** "Standard sustain pedal"
  - **Forward:** "Hold a forward loop"
  - **Ping-Pong:** "Hold a forward/reverse loop"
- A click on the key still opens the same menu, and choosing a mode works as before. No primary interaction changed.

**Nothing new on the card.**
- No pedal icon, knob, button or panel, and no colour.
- The test checks the card's child components against a card without the setting.
- The `[design-capture]` pixel identity and every product's visual regression pass at 0 px.
- It shows only in a product that has the parameter (ANDOR OSP). ANDOR Analog's named key and its menu are unchanged.

**States.**
- **Granular:** the three choices show inactive (the same items, quieter) and keep their check.
- **No loop:** a recording with no loop to offer adds one muted, inactive line: "No suitable loop found for this recording". A set or atlas with some members unable to loop says "No suitable loop for N of M recordings", and with none "No suitable loop found for these recordings". The main view never shows a warning.
- **Accessibility:** each choice has a title and description; the menu keeps its keyboard behaviour (Return, Space or Down opens it).
