# ANDOR Drums V1.1 — interface and keyboard mapping report

Branch `drum-plugin`, on top of `0df29bd`. Screenshots in `screens/` are real renders of
the plugin's editor, made by `andor_drums_plugin_tests "[snapshots]"` (xvfb, Linux), not
mockups.

## Stage A: audit of the starting point

The spec's summary was checked against the branch before building on it:

| Spec says exists | On the branch | Consequence |
|---|---|---|
| Nine engines, 2x4 / 3x3, PAD / EXPANDED, mapping ops, independent MIDI, chokes, shared effects | Yes (`0df29bd`) | Extended. |
| Round-robin playback | Engine support only (OSP `InstrumentSet`). The Drums loader builds one file per pad. | Not shown as a working control. The layer list says so; it's the next round. |
| Arpeggiator in Drums | Not wired (OSP's arp is not in the Drums processor) | No ARP control rendered (spec 12.2). |
| Per-pad modulation (LFO, ENV, VEL, NOTE, MW) | Not wired in Drums (each pad engine has OSP's `mod::` system, but no routes are exposed) | AMP envelope only; the others are marked "next round" (spec 11.4). |
| Blender knob | Not committed yet | The OSP knob is used; it switches automatically once the rendered knob lands. |

The mockup shows eight pads in one row. The spec text says 2 rows × 4. **The text was
followed** (2x4 default, 3x3 option). A 1x8 strip would only need another `PadGrid` layout
if wanted.

## Implemented

**Window.** Resizable from 0.7 to 1.5 of a 1280×900 base, with a fixed aspect ratio. The
content is laid out once and scaled as a whole, so every proportion, including the
equal pads, holds at any size. The hierarchy, from top to bottom: top bar (undo/redo, kit
summary, VOLUME); pad grid; PAD | EXPANDED, KEY MAP, PAD 9, 2x4 | 3x3; the selected pad's
sound; its AMP envelope; EFFECTS (whole kit); KIT MACROS (whole kit). There is no permanent
keyboard.

**Pads (`PadGrid`).** One component for every cell. The grid divides its area exactly, and
leftover pixels go to the margins, never to a cell. A cell's size cannot depend on its
content. Long names are truncated; selection is a ring drawn inside the cell bounds. The
states (empty, loaded, selected, playing, file drag-over, pad drag-over, muted, soloed or
silenced by another solo, missing, loading, load error) are all drawn in the same geometry.

- **One interaction pattern.** The waveform is the striking surface: press to play (louder
  towards the top) and select. The header and footer select without playing. The number
  badge is the handle: drag it onto another pad to swap places, with sounds and MIDI staying
  with their pads (undoable). S and M toggle solo and mute. ≡ or a right-click opens load,
  rename, category, choke, mute, solo, swap with… and clear. Double-click the name to rename.
- **Pad 9.** Always kept. In 2x4 a PAD 9 button appears when it holds a sound, and Auto Map
  includes it.

**Selected pad.** The pad's name (double-click to rename), ‹ › to step through pads, LOAD
and CLEAR, a large waveform with START shown, START / TUNE / GAIN / PAN / REVERSE, PLAY MODE
(one shot / gate), VOICES (poly / mono retrigger), CHOKE GROUP, CATEGORY, and the layer list.
AMP envelope: attack, decay, sustain and release per pad, with its drawn shape.

**KEY MAP (`KeyMapEditor`)** replaces the lower half while open; the pads stay visible and
playable.

- **Layout.** One lane per visible pad in screen order. Lanes and keyboard share one note→x
  mapping; the keyboard is equal-width semitone columns, so every key is exactly under its
  cells at any zoom. Zoom with − / + or Cmd/Ctrl+wheel; scroll with the wheel or the scroll
  bar; FIT shows the assigned zones; 0-127 shows the full range. Octave lines at overview
  zoom, semitone lines when there's room.
- **PAD mode.** One-key markers (pills). Drag a marker to move it; click any cell or key to
  give that lane's (or the selected) pad that note.
- **EXPANDED mode.**
  - Drag a block to move it; its width and root offset are kept.
  - Drag either edge to resize. `0 ≤ low ≤ high ≤ 127` always holds, and a zone can shrink
    to one key.
  - Drag the triangle to set the root, kept inside the zone. The root equal to the lowest
    key is the default.
  - Click an empty lane to create a one-octave zone.
  - While dragging, the new range shows as names and MIDI numbers.
  - Escape cancels. Nothing is written until the mouse is released.
- **Collisions.** Never applied silently. The block turns red and names the pad in the way.
  On release a menu offers:
  - Swap, when exactly one pad is in the way of a move or note.
  - Move the other zones to the nearest free place. This uses `drums::moveZoneToFreeSpace`,
    and if no place fits, nothing changes.
  - Layer, only with ALLOW OVERLAP. Overlapping keys are then hatched red.
  - Cancel. Dismissing the menu also cancels.
- **Inspector.** NOTE, or LOW / HIGH / ROOT, as editable numbers that accept "36" or "C2".
  It shows the range size and the transposition of the last key played ("G2 (43) plays +7
  st"). RESET returns the factory note or zone; CLEAR leaves the pad silent in this mode.
- **MIDI Learn.** PAD: play one key. EXPANDED: play the lowest key, then the highest, in
  either order. Only note-ons count, from any channel. Notes reach the editor through a
  lock-free FIFO, and the audio thread only writes it while Learn is armed. CANCEL, Escape,
  closing KEY MAP or 30 s of silence end Learn. A learnt result that collides goes through
  the same resolution as a drag.
- **Auto Map.** Standard Drum Kit, Compact Chromatic, One Octave Per Pad, Two Octaves Per
  Pad, Fit From Selected Root. It always previews first: a banner says how many pads change
  in which map, and APPLY or CANCEL decides. It changes only the active mode's map. When two
  octaves per pad don't fit (8 × 24 > 128), it says so and uses the widest width that fits
  (16 keys for 8 pads, 14 for 9). It never creates an invalid note.
- **Undo.** Every gesture is one transaction: zone move, resize, root, swap, note
  assignment, Learn, Auto Map, pad swap, rename, ALLOW OVERLAP, reset and clear.
  (`DrumsProcessor::applyEdit`; the arrangement is the key maps, the pad order and the
  names.) Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z work, plus the UNDO / REDO buttons.

**Engine and processor.**
- Sustain pedal (CC 64) holds gate pads.
- All-notes-off and all-sound-off release the pedal and every voice.
- New per-pad parameters: `padN.start`, `reverse`, `attack`, `decay`, `sustain`, `release`
  (version hint 2).
- State schema 2 adds `<Order slots="…"/>`. State 1 opens with pads in identity order
  (tested).
- Mapping edits are serialized state, not automatable parameters (spec 14.3). PAD /
  EXPANDED remains the automatable `keyboardMode` parameter.

**Active-note policy.** Voices finish normally. New note-ons use the current map. A note-off
ends exactly the voices its own note-on started (`DrumKitEngine::started`), even across a
mode switch, a map edit or the pedal. Tested with held notes and the pedal.

## Verified (automated, executed)

| Suite | Result |
|---|---|
| `osp_drums_tests` (mapping, engine) | see the final run in the commit message |
| `andor_drums_plugin_tests` | 15 cases, 471 assertions, all pass |
| OSP core suites and OSP plugin suite | see the final run in the commit message |

New coverage:
- **Layout.** 8 and 9 equal cells. A long name and a selection change nothing. Equal at
  minimum, 1.0 and maximum scale.
- **Pad 9 and swaps.** Pad 9 survives four layout switches. A swap keeps the sound and MIDI
  (the kick on 36 renders identically), and undo / redo work.
- **State.** The order is recalled, and a state-1 kit loads.
- **KEY MAP gestures.** Spec tests 2–4: kick 36–48 with root 36; MIDI 55 renders at +7
  semitones after the move; undo restores. A drag changes nothing until release. Escape
  cancels. Resize; a collision is refused and left pending; cancel; move-the-others in one
  undo step; root clamped to the zone; swap.
- **PAD mode.** Drag, swap, move-the-others. After every operation, no key in 0..127 plays
  two pads, and the EXPANDED map is untouched.
- **MIDI Learn through `processBlock`.** Not armed means nothing is queued. Note learn,
  range learn (highest key first), cancel mid-range, a colliding learn left pending,
  held-note display.
- **Auto Map.** A preview writes nothing; two octaves becomes 16 keys each with a message;
  apply; no overlaps; undo; only the active map changes.
- **Mode switch.** Held notes and the pedal across a mode switch: no stuck notes.

## Not tested (needs a Mac and people)

- DAW hosts (Logic, Live, REAPER), AU validation, real Retina output. The 2x snapshot is
  rendered offscreen at scale 2.
- Real mouse drags and the resolution popup menu in a window. The tests drive the same
  gesture API the mouse handlers call; the menu needs a window, which the headless tests
  don't have.
- Manual script tests 1–8 in a DAW.
- File drag-and-drop from Finder.

## Known limitations

- One sample per pad (round robin, velocity layers and stacks are next).
- No per-pad LFO / ENV / VEL / NOTE routes and no arpeggiator in Drums yet.
- No kit preset files yet; the session state holds everything.
- Pad polyphony is still applied at the host's next prepare.
- Moving a zone while its notes sound: they finish at their old pitch, and new notes use the
  new zone.
