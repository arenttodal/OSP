# ANDOR Drums V1.2 — Warm Ceramic + Teak, mockup layout

Brings ANDOR Drums in line with ANDOR/OSP's chosen look
(`docs/design/warm-ceramic-teak-style-guide.md`, direction 09) and moves the layout to the
user's Drums mockup. Screenshots in `screens/` are real renders of the editor.

## What came from OSP (merged from the default branch, 212a29d)

- The approved Blender macro knob (`SpriteKnobRenderer`, the `macro-ivory` packs at 176 and
  352 px). Drums draws it for all its macro knobs: DRIVE, MOVEMENT, ECHO and SPACE, plus
  LIFE, DYNAMICS and CHARACTER. Each knob sets `sprite = macro-ivory` and
  `spritePilot = true`, so the sprite shows under OSP's default knob skin. OSP's own
  behaviour is unchanged.
- OSP's vector knobs (layer and mini), fonts, palette and macro colours, unchanged.

## The skin (`apps/drums/Source/CeramicSkin.*`)

Drawn in code from the guide's displayed colours and dimensions. Blender is not available
in this environment, so the guide's rendered 9-slices and sprites for these parts are not
made yet; the code draws the same forms in their place.

## Layout (base 1536 × 1024, scaled 0.6–1.25×, fixed aspect)

From top to bottom:

1. **Top bar.** The ANDOR / DRUMS wordmark; the kit bar (undo, the kit name, redo); the
   pad layout switch with the PAD 9 button; VOLUME with its output meter.
2. **Pads.** One row of 8 by default, as the mockup. 2 × 4 and 3 × 3 remain; the window
   grows taller for them (+150 and +230 px) instead of squeezing the cells. Cells are
   equal in every layout (tested).
3. **The selected pad.**
   - Badge, name, ‹ ›, the SAMPLE | KEY MAP tabs, the file name and a menu.
   - A large waveform with a draggable START handle; START, TUNE and REVERSE below it.
   - The sample layer list (audition with ▶, Replace Sample…).
   - PLAY MODE, CHOKE GROUP, One Shot, VOLUME and PAN.
4. **KEYBOARD RANGE**, always visible: every pad's note or zone on one 0–127 keyboard,
   with the pad numbers above. It has PAD | EXPANDED, ROOT NOTE (lowest key, middle or
   highest key of the selected pad's zone, as one undo step) and ZONE PRESETS (which
   opens KEY MAP with the preview). The keyboard button opens KEY MAP, and clicking a
   zone selects its pad.
5. **Bottom row.**
   - MODULATION: the AMP envelope; other sources are marked "next round".
   - EFFECTS (KIT): power key, rendered knob and value per effect. The power key goes to
     0 % and back to the last setting.
   - GLOBAL (KIT): LIFE, DYNAMICS and CHARACTER with lens LEDs.

KEY MAP opens over the selected-pad area and the keyboard range, so the pads and the
bottom row stay visible.

State: the layout (`1x8` / `2x4` / `3x3`) and the kit name are saved in `<View>`. Kits saved
with `2x4` or `3x3` keep their layout; new kits start in `1x8`.

## Keyboard range (as the mockup)

A real piano (75 equal white keys for MIDI 0-127, black keys narrower and shorter on top).
Colour is drawn per key, inside each key's own shape, so it never spills onto a
neighbour: a mapped white key's face takes its pad's colour (the black keys are drawn on
top, so only the visible face is tinted); a mapped black key keeps a dark rim around a
darkened tint of its pad's colour. Above the keys, a slim rounded cap marks each run of
keys one pad owns; a white key's cap gives up the half of a neighbouring black key that
belongs to another pad, so caps never overlap. The selected pad's cap has a stronger
outline, and the pad number sits above its cap (the selected pad's in the accent colour).
Colours are sampled from the mockup's tabs: kick `#e8895b`, snare `#819ec6`, closed hat
`#a2bca1`, open hat `#91ad96`, clap `#b8a996`, tom `#9d87b6`, rim `#afafad`, percussion
`#e5b779`, plus cymbal `#86b4b0`, which the mockup does not show. ROOT NOTE and ZONE PRESETS
moved into the title row, so no pad number is ever covered. Snapshot:
`screens/03b-keyboard-range-expanded.png`.

## Not done (needs a decision or tools)

  that Drums does not expose as parameters yet.

## A bug found on the way

JUCE composites an image at the alpha of the current colour. The teak was drawn just after
its contact shadow, which had set a 10 % colour, so the wood came out nearly invisible. The
fix is `setOpacity (1)` before drawing it. A test now checks that the cheek renders as
opaque teak.
