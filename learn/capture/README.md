# ANDOR Learn Capture Studio

Development-only tooling that films the real ANDOR OSP editor for the public Learn guides.
Nothing here is part of the plugin, its bundles, the release script or `ctest`
(`OSP_BUILD_LEARN_CAPTURE` is OFF by default). Design: `docs/learn-studio/gate-0-report.md`;
results: `docs/learn-studio/gate-1-report.md`.

## Regenerate

```sh
# once per machine (Linux): JUCE's build headers (see .github/workflows/ci.yml), plus
sudo apt-get install -y xvfb openbox x11-utils ffmpeg && pip install pillow

cmake -B build-plugin -G Ninja -DOSP_BUILD_PLUGIN=ON -DOSP_BUILD_LEARN_CAPTURE=ON
cmake --build build-plugin --target osp_learn_capture

learn/capture/tools/capture.sh                      # every scene
learn/capture/tools/capture.sh c2-grab-last         # one scene
python3 learn/review/build.py                       # the review page (learn/review/index.html)
python3 -m http.server -d learn 8000                # then open http://localhost:8000/review/
```

`capture.sh` exits non-zero if any scene fails; a failed scene keeps its previous assets and its
`learn/capture/out/<scene>/run.json` / `post-report.json` say why (with `failure-last-frame.png`).

## Layout

| Path | What | In Git |
|---|---|---|
| `scenarios/*.json` | one scene each (`andor.learn.scenario`, schema in `docs/learn-studio/content-and-scenario-model.md`) | yes |
| `runner/LearnCapture.cpp` | the runner: real processor and editor on an Xvfb desktop window, real window events, audio pumped per frame, expectations | yes |
| `tools/xvfb-wm.sh` | Xvfb with `-noreset` and openbox (both required: Gate 1 stability report) | yes |
| `tools/post.py` | fixed crop, pointer / outline / file badge, WebM + MP4, poster, step stills, checks, manifest entry | yes |
| `tools/capture.sh`, `tools/manifest.py` | the whole run; `learn/assets/osp/manifest.json` | yes |
| `fixtures/input-phrase-d4.wav` | the live-input fixture (generated by the runner from fixed seeds) | yes |
| `fixtures/Tutorial *.wav` | OSP's own tutorial sounds (regenerated by `TutorialSounds.cpp`) | no |
| `out/<scene>/` | lossless master (`master.mkv`, RGB, 2x), `frames.json`, `run.json`, PNG poster | no |
| `../assets/osp/<scene>/` | web delivery: `.webm`, `.mp4`, `poster.webp`, `steps/*.webp`, `entry.json` | yes |

## Rules the runner enforces

- Actions inside `steps` are window events (click, key, drag, wheel) or the editor's own drop
  handler. Direct state changes (`setParam`, `addLayers`, `expandArp`, `arpLink`, input history)
  are accepted only in `start.setup` and are never filmed.
- Every step's `expect` must hold or the scene fails; `waitFor` fails on timeout. Prefer
  `paramText` (the value as displayed) over raw indices.
- Nothing is approved automatically: `entry.json` has `"approved": false` until the owner approves.

## Timing (read before judging motion)

The capture runs on a frame clock: each video frame advances the audio by exactly 1600 samples
(48 kHz / 30 fps) and runs the message loop once. Everything driven by audio (meters, read heads,
the arpeggiator's steps, SATELLITE's position, the CAPTURE page's level picture and clock) moves at
its true speed in the video. Rendering a 2x frame takes about 0.2 s here, so things timed by the
wall clock run faster in the video than in real use: background analysis and mapping, toast
notices, the REC dot's pulse. Tooltips are switched off for the same reason.
